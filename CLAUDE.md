# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Snakemake pipeline that trains ChromBPNet models on ATAC/DNase BAMs, then runs prediction, contribution scores, TF-MoDISco motif discovery (+ MEME export), Fi-NeMo motif hit calling and TOBIAS BINDetect footprinting on the contribution tracks. Runs on a SLURM cluster (IRB Barcelona); GPU rules use RTX 3090s in `irb_gpu_3090` (max 2 GPUs per user at a time) and, for short jobs, the preemptible `spot_gpu` (see GPU partitions below).

## Running

All commands run from the repo root (paths like `config/...`, `data/...` are relative to it).

- Full run (SLURM head job; extra args pass through to snakemake): `sbatch slurm_run_pipeline.slurm`
  - It activates the `snakemake` conda env, unlocks and cleans shadow dirs, then runs `snakemake --profile config/snakemake_profile/slurm "$@"`.
- Dry run / DAG check (safe in the login shell): `snakemake -n --profile config/snakemake_profile/slurm` (add the same `--configfile` you would pass to the head job).
- Single target: `snakemake -n --profile config/snakemake_profile/slurm <output_path>`, e.g. `pred_bw/<sample>_fold_0_chrombpnet_nobias.bw` (relative to `output_dir`). Swap `-n` for a real run only through the sbatch head job.
- Small end-to-end test (2 downsampled samples, 2 folds, 2 epochs, generated splits): `sbatch slurm_run_pipeline.slurm --configfile config/test/config.yaml`. Output dir `/scratch/qscd/dfernandezp/chrombpnetTest`; its downsampled BAMs live in `input_bams/` there (see `config/test/samples.tsv`).
- GPU sanity check: request target `logs/gpu_test/tensorflow_gpu_check_successful.flag` (rule `gpu_test_rule`, script `workflow/scripts/test_gpu_chrombpnet.py`). `..._successful_<n>.flag` runs extra copies (e.g. to check the partition routing in `logs/gpu_routing.log`).

There are no unit tests; validate changes with `snakemake -n -p` (and `--lint`). The python scripts in `workflow/scripts/` (fold averaging, `parallel_contribs.py`, `merge_contribs.py`, `modisco_to_meme.py`...) are standalone CLIs and can be tested on tiny files inside the chrombpnet image (`singularity exec --bind /home,/scratch/qscd <image> python ...`; DeepSHAP also runs on CPU for a few regions). Run anything heavier than that through `sbatch`/`srun`.

The profile (`config/snakemake_profile/slurm/config.yaml`) uses the SLURM executor, `use-singularity` with `--bind /home,/scratch/qscd --nv` (GPU passthrough), conda for TOBIAS and Fi-NeMo, `keep-going`, `slurm-requeue` (see GPU partitions) and default account `qscd` / partition `irb_cpu_iclk`.

## Configuration

- `config/config.yaml`: genome build, output dir (`/scratch/qscd/dfernandezp/chrombpnet`), folds to run (`folds: ["0"]` by default), MACS3/ChromBPNet/MoDISco params, contribution score chunking (`contribs`), QC MoDISco (`qc_modisco`), Fi-NeMo (`finemo`), container images. The chrombpnet image is pinned by digest because rules call its internal modules (`python -m chrombpnet....`); check them again before changing it. Note the keys are spelled `chromnpnet_bias` / `chromnpnet_model` (typo is load-bearing; rules reference these exact names).
- `config/samples.tsv`: `SampleName`, `BamPath` (multiple BAMs separated by `;`, merged per sample), `UseForBiasModel` (`True` samples' BAMs are all pooled into a single bias model).
- `config/resources.yaml`: per-rule `mem_mb`/`runtime` (minutes)/`cpu`/`retries`, plus `gres`/`slurm_partition` for GPU rules, and the `gpu_routing` block. Every rule reads its resources via `RESOURCES["<rule_name>"]`, so adding a rule means adding an entry here. The SLURM plugin takes CPUs from `threads:` (the `cpu` key only feeds it).
- Fold splits: `splits_dir` (default `config/chr_splits`, pre-made mm10 `fold_N.json`) is used as is. If `splits_dir: ""`, rules `get_canonical_chrom_sizes` + `make_chr_splits` generate them with `chrombpnet prep splits` from `chr_splits.folds` (test/valid chroms per fold) into `<output_dir>/chr_splits/`. Rules refer to the fold file through the `FOLD_JSON` global.
- `config/Blacklist/`: vendored ENCODE Blacklist repo; the pipeline only uses `lists/<build>-blacklist.v2.bed.gz` unless `custom_blacklist` is set.

## Architecture

`output_dir` holds everything that is not pipeline code/config: the Snakefile sets `workdir: OUTPUT_DIR`, so `.snakemake/` (singularity images, conda envs, metadata, slurm logs, shadow dirs), downloaded reference data (`data/`), the singularity pull cache (`.singularity_cache/`), the conda package cache (`.conda_pkgs/`), tmp files and results all go there. Point it to `/scratch` for real runs (home has a small quota). Consequences: relative paths in the config (sample sheet, its BAMs, resources, blacklist, `splits_dir`, `output_dir`) are relative to the repo root and must be wrapped in `repo_path()` in the Snakefile *before* the `workdir:` line (SLURM rule jobs re-parse the Snakefile from inside `output_dir`, so the current directory can't be used); rule inputs/outputs are written as plain relative paths (no `OUTPUT_DIR` prefix, so no f-strings unless a value like `TOP_N_PEAKS` is interpolated) and resolve inside `output_dir`. Singularity binds `/home` and `/scratch/qscd` (never the whole `/scratch`: the chrombpnet image has its code and data under `/scratch/chrombpnet`, which would be hidden), so `output_dir` must be under one of them.

`workflow/Snakefile` loads config, parses the sample sheet into `SAMPLES` and `ALL_BIAS_BAMS`, defines shared globals (`OUTPUT_DIR`, `GENOME_FASTA`, `TOP_N_PEAKS`, `FOLDS`, ...) used by all rule files, sets `TMPDIR`/`SINGULARITY_TMPDIR` to `<output_dir>/<host_tmp_dir>`, then includes rules in order (later files reference `rules.<name>.output` from earlier ones):

0. `common.smk`: GPU partition routing (`gpu_partition()`) and `thread_env()` (caps the thread pools of TensorFlow/OpenBLAS/numba to the job's CPUs; GPU/MoDISco rules `export` it).
1. `prepare_data.smk`: downloads genome FASTA, chrom sizes, JASPAR motifs into `<output_dir>/data/`; unzips the blacklist; merges/sorts/indexes per-sample BAMs (`scripts/merge_sort_index_bams.sh`: coordinate-sorted inputs are symlinked or merged without re-sorting).
2. `generate_bias_model.smk`: pools all bias BAMs → MACS3 → blacklist filter (blacklist slopped by 1057 bp = half ChromBPNet input) → top-N peaks (`scripts/filter_top_peaks.py`: canonical chromosomes only (`chr_splits.canonical_chroms_regex`), exactly N by column 7, original order) → `chrombpnet prep nonpeaks` → `chrombpnet bias train` per fold. The bias QC that `chrombpnet bias pipeline` would run in the same GPU job is split so model training doesn't wait for it: `bias_qc_gpu` (predictions + DeepSHAP on 30K peaks), `bias_qc_modisco` (CPU, per `{head}` profile/counts) and `bias_report` (`make_html_bias -icmd pipeline` → `evaluation/overall_report.html`).
3. `preprocessing.smk`: the same peak/nonpeak steps per sample.
4. `training.smk`: `chrombpnet train` per sample × fold, using the fold's shared bias model. Produces `*_chrombpnet_nobias.h5` (and `*_train_report.html`).
5. `qc.smk`: the QC of `chrombpnet pipeline`, rebuilt from parts: `chrombpnet_qc_gpu` (test-set metrics with `python -m chrombpnet.training.predict`, marginal footprints of the bias motifs in `workflow/motifs/` → max bias response), `chrombpnet_qc_modisco` (CPU MoDISco on the first `qc_modisco.n_regions` rows of the fold's all-peaks contribs) and `chrombpnet_report` (`make_html -icmd pipeline` → `evaluation/<sample>_overall_report.html`). No GPU DeepSHAP on a separate 30K subsample.
6. `prediction.smk`: per sample × fold `pred_bw` and `chrombpnet footprints` (motifs from `footprints.motifs_to_pwm` inserted in the fold's test-chromosome nonpeaks); contribution scores via `split_contribs_regions` (shuffles the sample's peaks with a fixed seed and splits them into `contribs.n_chunks` beds, identical for all folds) → `contribs_chunk` (GPU; `scripts/parallel_contribs.py` runs `contribs.procs_per_gpu` chrombpnet interpret processes on the job's GPU) → `merge_contribs` (CPU; `scripts/merge_contribs.py` concatenates in order and writes the bigwigs with chrombpnet's `bigwig_helper`). Final files are those of `chrombpnet contribs_bw`, **but their rows are in shuffled order** (TF-MoDISco's `-n` cap keeps seqlets in region order). Per sample `modisco motifs` + `modisco report` on the fold-averaged profile scores, and `modisco_meme` (`scripts/modisco_to_meme.py`, trimmed PFMs).
7. `fold_average.smk`: per sample, averages folds (`{sample}_mean*` outputs) with `scripts/average_bigwigs.py` (prediction and contribution bigwigs) and `scripts/average_contribs_h5.py` (contribution h5; requires identical `interpreted_regions.bed` across folds). With one fold the mean equals that fold.
8. `tobias.smk`: merges all samples' (fold-averaged) interpreted regions into consensus peaks, then runs TOBIAS BINDetect twice (profile and counts contribution bigwigs as "footprint" signals, one condition per sample). Uses the conda env `workflow/envs/tobias.yaml` (bioconda `tobias` package; installing it with pip no longer builds), not a container, and forces `TMPDIR=/tmp`.
9. `finemo.smk`: Fi-NeMo on each sample's fold-averaged profile contribs (same h5 as MoDISco; the mean bed gives the peak coordinates in the same row order) and its MoDISco h5: `finemo/<sample>/hits/` (hits.tsv, hits_unique.tsv, hits.bed) and `finemo/<sample>/report/` (motif_occurrences.tsv = hits per motif per peak). Conda env `workflow/envs/finemo.yaml` (PyPI torch wheel with bundled CUDA); `finemo_call_hits` needs a GPU.

`wildcard_constraints` in the Snakefile restrict `sample` to the sample names, `fold` to digits, `chunk` to 3 digits and `head` to profile/counts, which keeps `{sample}_fold_{fold}*`, `{sample}_mean*` and chunk patterns unambiguous.

GPU partitions: `irb_gpu_3090` (irbgcn01) runs at most 2 GPUs per user (QOS `gpulimits`); `spot_gpu` has more 3090 nodes and no limit, but jobs can be preempted. A single job can't target both (different QOS, `EnforcePartLimits=ALL`), so `gpu_partition()` picks one per job at submission time from `slurm_partition` in resources.yaml: `main` (training: always `irb_gpu_3090`), `auto` (short jobs: `irb_gpu_3090` while the user has < `gpu_lane_limit` jobs there per `squeue`, else `spot_gpu`; retries after a failure go to `irb_gpu_3090`) or a fixed name. Decisions go to `logs/gpu_routing.log`; the callable returns the main partition in dry runs and inside cluster jobs. The cluster has `JobRequeue=0`, so the profile sets `slurm-requeue: true`: without it a preempted job is cancelled while the slurm plugin keeps waiting for it. Rules that can land on spot must therefore be restartable from scratch. Always request `gpu:rtx3090` (TF 2.8 in the chrombpnet image JIT-compiles and hits cuDNN errors on the H200s; 4090s are also unsupported).

Conventions to preserve:
- ChromBPNet refuses to write into an existing output dir, but Snakemake pre-creates output parents. Training rules therefore write to a `tmp_*` dir, `mv` it to the final location, and touch a `complete.flag`. They rename chrombpnet's train-only `overall_report` to `train_report`; the full `evaluation/*overall_report.html` QC reports (used to tune `bias_thresh_factor`) are written by the report rules into the same model dirs, with the file names chrombpnet's report generators expect (QC rules write there too, so keep those names). `chrombpnet qc` / `bias qc` can't be used standalone (they require a new output dir but read `auxiliary/filtered.*` from it).
- Contribution score chunk files are `temp()` unless `contribs.keep_chunks`; changing `contribs.n_chunks` or `shuffle_seed` recomputes all contribution scores.
- `chrombpnet prep nonpeaks` rules use `shadow: "minimal"` (hence `--cleanup-shadow` in the head script).
- Most rules run inside `chrombpnet_container` (which also provides samtools/bedtools/modisco); MACS3 and bedtools-only steps use their own biocontainers. The MoDISco MEME db path points inside the ChromBPNet image.
- `/scratch` purges files with mtimes older than ~60 days, and conda keeps the packages' original mtimes, so an `onstart:` handler in the Snakefile touches `.snakemake/conda` and `.conda_pkgs` on every run. If an env breaks anyway (e.g. `ModuleNotFoundError` inside it after a long pause), delete those two dirs in `output_dir`.
- The Snakefile uses nested same-quote f-strings, which requires Python ≥ 3.12 in the snakemake env.
